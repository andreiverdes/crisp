what it stands for

Five letters, five promises.

CRISP is an acronym and a verb. Each letter is a design goal, and each goal has rules a human or a model can check.

C

Concise

Say everything necessary, nothing unnecessary. Fewer tokens, same meaning.

say it once, then stop
R

Relevant

Only what helps the question at hand. On-topic answers, no fluff, no unasked tangents.

keep what changes action
I

Intuitive

Understood on first read. Answer first, natural order, structure that's easy to follow.

answer first
S

Simple

The plainest words that keep the precision. Straight to the point, less cognitive load.

plain words, same words
P

Protocol

Not a vibe: ten explicit rules, each with a yes/no check. Repeatable by people and models.

every rule has a check

the protocol

Ten rules. Each one has a check.

When rules conflict: no ambiguity, then easy to understand, easy to scan, relevant, conversational, simple, concise, few tokens. Precision is never traded for length. Full protocol, reasons, and research →

01
Answer firstThe first sentence is the answer, decision, result, or ask.
02
Say it onceNo preview, recap, restated question, or restated shared context.
03
Keep what changes actionDelete any sentence whose removal breaks nothing.
04
Plain words, same wordsCommon verbs; one term per concept; no intensifiers without a measurement.
05
Name the actor, state the condition“If X, do Y.” “X failed because Y.”
06
Replace vague with checkableSoon, appropriate, usually become a number, a name, a condition, or “unknown”.
07
Structure is earnedProse by default; lists, tables, headings only when they aid scanning.
08
Short is not crypticKeep code, corrections, risks, and real uncertainty. No telegraphese.
09
Sound like a colleagueNo flattery, ceremony, apology, or ritual hedges. Disagree plainly.
10
StopNo closing summary, no “let me know”.

three depths

Same rules, more or less detail.

Levels change how much is said, never how well.

/crisp 1just the answer

Use Redis, with a TTL on each session key.

/crisp 2default

Use Redis, with a TTL on each session key. Set maxmemory-policy volatile-ttl so eviction only removes keys that have a TTL.

/crisp 3plus the why

Use Redis, with a TTL on each session key: sessions are small, short-lived, and read on every request. Set maxmemory-policy volatile-ttl so eviction only removes keys that have a TTL. If you don't run Redis yet, Postgres works. Risk: a Redis restart without persistence logs everyone out.
